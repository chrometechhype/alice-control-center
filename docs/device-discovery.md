# Заметки по устройству и исследованию

Дата последней проверки: 2026-10-26. Данные получены с собственной станции по SSH, только чтение,
кроме проверки LED и записи временного скрипта в `/tmp`.

## Обнаруженная станция

| Параметр | Значение |
| --- | --- |
| Hostname | `Yandex-Lite-gen2-XXXX` |
| Model raw | `Yandex Prune EVT2` |
| Определённая модель | Станция Лайт 2 |
| Прошивка / Quasar | `0.372.1.13.4794666714.20261021.136` |
| Ядро | `4.9.113` |
| Архитектура | `aarch64` |
| ОС | Buildroot 2020.02.1 |
| CPU | Amlogic, 4 ядра |
| RAM | ~238 МиБ |

Пароль в документацию и исходники не переносится. Он хранится только в локальном
`data/config.json` (права `0600`) и вводится в мастере подключения.

## Что доступно

- **Shell:** BusyBox 1.31.1, `/bin/sh`, `usleep`, `awk`, `sha256sum`, `printf`.
- **SFTP:** отсутствует (`sftp-server` не установлен). Панель использует shell-каналы:
  чтение — `cat`, запись — `cat > file` с контролем завершения по `exit-status`.
- **LED:** узлы `/sys/class/leds/plum:<red|green|blue>:ringN/{brightness,trigger}`.
  Штатный триггер — `led_ring_fb`.
- **Звуки:** `/system/vendor/quasar/sounds` (системные), `/data/sounds` (пользовательские).
- **YAM:** `/data/quazar/yam`.
- **Логи демонов:** `/data/quasar/daemons_logs`.
- **Пользовательские данные:** `/data/opt` (единственный удобный каталог для записи вместе с
  `/data/sounds`).
- **Bluetooth:** `bluetoothctl` присутствует; доступны `show`, `devices`, `list`, сканирование и
  сопряжение. Набор команд зависит от прошивки.
- **LED-анимация:** проверена запись кадров в sysfs на частоте до 60 FPS. Анимация запускается
  на самой колонке одним процессом, чтобы не открывать SSH-канал на каждый кадр.

## Проверка SSH-стабильности

Первый вариант анимации выполнял отдельный `exec` на каждый кадр. На 8 FPS это создавало десятки
каналов в секунду: sshd отвечал `Unable to exec` / `transport closed`, соединение падало примерно
каждые две минуты.

Текущий вариант:

1. Backend генерирует один shell-скрипт с кадрами и `usleep`.
2. Скрипт пишется в `/tmp/acc-led-anim.sh` одним shell-каналом.
3. Запуск: `nohup sh /tmp/acc-led-anim.sh`.
4. Остановка: stop-файл + PID-файл, затем `led_ring_fb`.

Тест: 24 кадра, 60 FPS, 25 повторов (~10 секунд). Статус соединения оставался `connected`,
каналы не переполнялись.

Бесконечный режим проверен отдельно: 6 кадров, 20 и 60 FPS, по 8 секунд. Состояние оставалось
`connected`, `animation.running = true`, остановка через `/led/restore` возвращала `led_ring_fb`.
Долговременная стабильность бесконечного цикла на 60 FPS не гарантируется — см. предупреждение
о перезагрузке ниже.

Отдельно зафиксировано: во время одного стресс-теста станция перезагрузилась через несколько минут
после анимации (uptime сбросился). Причина не подтверждена; возможно, обновление прошивки или
перегрузка LED-контроллера. Панель не вызывает перезагрузку. Для длительных сцен рекомендуется
20–30 FPS.

## Ошибка записи файлов через shell

На этой прошивке `cat > file` возвращает `exit-status`, но не присылает SSH `close`. Из-за этого
запись «зависала» до 30-секундного таймаута, хотя файл уже был записан. Исправление в
`server/adapters/SshAdapter.ts`: завершать операцию по событию `exit` с небольшой задержкой и
принудительно закрывать канал, не ожидая `close`.

## Определение модели

Порядок в `src/lib/deviceVisual.ts`:

1. Лайт 2: `лайт 2`, `lite 2`, `lite-gen2`, `prune`, `plum`.
2. Дуо Макс, Станция 3, Станция 2, Мини 3 Про, Мини с часами, Мини 3, Миди, Стрит, Макс,
   Мини, Лайт.
3. Иначе — «Яндекс Станция» без изображения.

Цвет корпуса и часы прошивка не сообщает. Панель хранит выбор пользователя в `localStorage`
(`acc-station-look`), по умолчанию — зелёный, без часов. Акценты интерфейса считаются из цвета
корпуса и применяются через CSS-переменные и `color-mix`.

## Официальные изображения

Изображения станций взяты с официальных продуктовых страниц Яндекса
(`avatars.mds.yandex.net`), приведены к 640 px, прозрачный фон, WebP. Лежат в `public/devices/`.

## Ограничения исследования

- Проверена одна модель (Лайт 2); остальные определения основаны на hostname/model и официальных
  изображениях.
- Нет доступа к закрытым API Алисы: панель управляет только тем, что доступно через файловую
  систему и разрешённые команды.
- Некоторые sysfs-узлы и Bluetooth-команды могут отличаться на других прошивках.
- Панель не устанавливает сторонние компоненты и не изменяет системные разделы без бэкапа.
