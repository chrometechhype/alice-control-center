# Alice Control Center 1.0.0 Alpha 13

Выпуск про установку. Панель теперь ставится одной командой не только на Windows: на Linux и macOS
та же строка скачивает релиз, сверяет контрольную сумму и поднимает панель в фоне. А сбой сети при
скачивании зависимостей больше не выглядит как загадочный `ERR_SOCKET_TIMEOUT` из недр npm.

![Alice Control Center](https://raw.githubusercontent.com/chrometechhype/alice-control-center/main/docs/cover.png?v=1.0.0-alpha.13)

## Добавлено

- **Установка одной командой на Linux и macOS.** Установщик проверяет Node.js 20+ и `npm`,
  скачивает последний релиз GitHub, сверяет SHA-256 — без совпадения контрольной суммы установка
  отменяется. Ставит панель в `~/.local/share/AliceControlCenter`, сохраняя `data/` при обновлении,
  запускает её в фоне и оставляет `acc-start.sh` для повторного запуска. Другая папка и конкретная
  версия задаются переменными `ACC_INSTALL_DIR` и `ACC_VERSION`.

## Исправлено

- **Установка падала на медленной сети.** npm обрывал скачивание пакета с `ERR_SOCKET_TIMEOUT`,
  хотя архив уже был распакован, — со стороны это выглядело как «установка упала непонятно почему».
  Теперь зависимости скачиваются с тремя попытками и длинными таймаутами. Если сеть так и не
  отпустила, установщик называет причину, подсказывает про прокси и зеркало registry и даёт команду
  доустановить вручную.
- **Лишние полторы сотни пакетов при установке.** `tsx` переехал в обычные зависимости, поэтому
  панель ставится без тестов, сборщика и jsdom: 203 пакета вместо 353. Заодно пропали
  предупреждения `EBADENGINE` про Node 20 от тестовых пакетов.

## Как обновиться

Панель обновляет себя сама: «Проверить обновления» → «Установить». Настройки, история, бэкапы и
сценарии в `data/` сохраняются.

Установка с нуля:

```powershell
irm https://raw.githubusercontent.com/chrometechhype/alice-control-center/main/install.ps1 | iex
```

```sh
curl -fsSL https://raw.githubusercontent.com/chrometechhype/alice-control-center/main/install.sh | sh
```

- 229 тестов в 22 файлах; `npm run typecheck` и `npm run build` проходят.
- Живые проверки: установка на чистую папку подняла панель и ответила `200`; повторный запуск
  установщика остановил старую панель и сохранил `data/`; набор только с рабочими зависимостями
  (`--omit=dev`, 203 пакета) запускает панель и тоже отвечает `200`.
