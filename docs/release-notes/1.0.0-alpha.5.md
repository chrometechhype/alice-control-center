# Alice Control Center 1.0.0 Alpha 5

Выпуск про сравнение версий. Панель на alpha.3 показывала в карточке «Последняя — 1.0.0-alpha.4», но
после проверки отвечала «Установлена актуальная версия (1.0.0-alpha.3)» и не качала обновление.
Причина: при разборе номера отбрасывался суффикс `-alpha.N`, и все альфы выглядели как одна и та же
версия 1.0.0.

![Alice Control Center](https://raw.githubusercontent.com/chrometechhype/alice-control-center/main/docs/cover.png?v=1.0.0-alpha.5)

## Что исправлено

- **Альфы сравниваются по номеру.** Порядок теперь по SemVer: `1.0.0-alpha.3` < `1.0.0-alpha.4` <
  `1.0.0-alpha.10` < `1.0.0-beta` < `1.0.0`; метаданные сборки (`+build`) не влияют. Числовые
  идентификаторы сравниваются как числа, поэтому `alpha.10` не «меньше» `alpha.9`.
- **Проверка больше не врёт.** «Установлена актуальная версия» появляется только при совпадении
  номеров; иначе — «Доступна версия 1.0.0-alpha.N» и кнопка установки, которая действительно скачивает
  архив и проверяет SHA-256.

## Как обновиться — один раз вручную

Исправление находится внутри панели, поэтому alpha.1–alpha.4 не умеют обновляться до alpha.5 сами:
их проверка всё ещё считает номера одинаковыми. Нужен один запуск установщика:

```powershell
irm https://raw.githubusercontent.com/chrometechhype/alice-control-center/main/install.ps1 | iex
```

Или скачать `Alice-Control-Center-1.0.0-alpha.5.zip` со страницы релизов и распаковать поверх
установки. Настройки, история, бэкапы и сцены в `data/` сохраняются. После alpha.5 автообновление
между альфами работает без ручных шагов.

## Качество

- 129 тестов в 15 файлах; шесть новых в `tests/updateVersion.test.ts`: порядок альф, числовые
  идентификаторы, релиз выше пререлиза, короткий пререлиз ниже длинного, метаданные сборки, обычные
  major/minor/patch.
- `npm run typecheck` и `npm run build` проходят.
